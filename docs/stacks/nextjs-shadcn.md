# Stack profile: Next.js + shadcn/ui (default)

## Overview

One TypeScript app that serves both the UI and the API.

| Layer | Choice |
| --- | --- |
| Framework | Next.js (App Router), TypeScript, Turbopack dev server |
| UI | Tailwind CSS v4 + **shadcn/ui** components + lucide-react icons |
| API | Route handlers (`app/api/**/route.ts`) and server actions |
| Data | PostgreSQL + Drizzle ORM, SQL migrations with drizzle-kit |
| Unit tests | Vitest + Testing Library |
| Acceptance tests | Playwright + **playwright-bdd** running the `.feature` files |
| Package manager | pnpm |
| App folder | `apps/web` |

## When to pick it

- You are building a web product and want **one app, one language, one deploy**.
- You want server rendering (fast first load, good SEO) and an API without a second service.
- **Pick something else** if the backend must be in another language (pair [`react-vite-shadcn`](react-vite-shadcn.md) or this profile with an API profile), or if you need long-running background work (add a worker app later).

## Commands

Create the app (from the repo root):

```bash
pnpm create next-app@latest apps/web --ts --tailwind --eslint --app --src-dir --import-alias "@/*" --use-pnpm
cd apps/web
pnpm dlx shadcn@latest init                        # pick a base color; writes components.json + theme CSS variables
pnpm dlx shadcn@latest add button card input label dialog sonner skeleton
pnpm add drizzle-orm pg zod
pnpm add -D drizzle-kit @types/pg vitest @vitejs/plugin-react jsdom @testing-library/react @testing-library/jest-dom \
  @playwright/test playwright-bdd
pnpm exec playwright install --with-deps chromium
```

`package.json` scripts (Shipright expects these names):

| Script | Command | Used by |
| --- | --- | --- |
| `dev` | `next dev` | you, Playwright `webServer` |
| `build` | `next build` | verify, Docker |
| `start` | `next start` | local production check |
| `lint` | `eslint .` | verify |
| `typecheck` | `tsc --noEmit` | verify |
| `test` | `vitest run` | verify |
| `test:bdd` | `bddgen && playwright test` | verify, `/build`, CI |
| `db:generate` | `drizzle-kit generate` | after editing `src/db/schema.ts` |

## Testing & BDD runner

**Acceptance (Gherkin)** — `playwright.config.ts` reads the feature files straight from the spec folders:

```ts
import { defineConfig, devices } from "@playwright/test";
import { defineBddConfig } from "playwright-bdd";

const testDir = defineBddConfig({
  features: "../../specs/*/02-scenarios/*.feature",
  steps: "tests/steps/**/*.ts",
});

const baseURL = process.env.BASE_URL ?? "http://localhost:3000";

export default defineConfig({
  testDir,
  use: { baseURL, trace: "on-first-retry" },
  projects: [{ name: "chromium", use: { ...devices["Desktop Chrome"] } }],
  // Against a deployed URL (BASE_URL set) no local server is started.
  webServer: process.env.BASE_URL
    ? undefined
    : { command: "pnpm dev", url: `${baseURL}/api/health`, reuseExistingServer: !process.env.CI },
});
```

Step definitions — `tests/steps/poll.steps.ts`:

```ts
import { expect } from "@playwright/test";
import { createBdd } from "playwright-bdd";

const { Given, When, Then } = createBdd();

Given("I am on the polls page", async ({ page }) => {
  await page.goto("/polls");
});

When("I create a poll called {string}", async ({ page }, title: string) => {
  await page.getByRole("button", { name: "New poll" }).click();
  await page.getByLabel("Title").fill(title);
  await page.getByRole("button", { name: "Create" }).click();
});

Then("I see {string} in the list", async ({ page }, title: string) => {
  await expect(page.getByRole("listitem").filter({ hasText: title })).toBeVisible();
});
```

Run one scenario by tag: `pnpm test:bdd --grep @LUNCH-03`. Run smoke tests against a deployed URL: `BASE_URL=https://… pnpm test:bdd --grep @smoke`. Add `.features-gen/` (generated by `bddgen`) to `.gitignore`.

Prefer `getByRole` / `getByLabel` locators — they test what users see and keep the app accessible. Use `data-testid` only for things with no accessible name.

**Unit** — `vitest.config.ts` with `environment: "jsdom"` and `@vitejs/plugin-react`; put tests next to the code as `*.test.ts(x)`.

## Container

`next.config.ts` must produce a self-contained server:

```ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = { output: "standalone" };

export default nextConfig;
```

`apps/web/Dockerfile`:

```dockerfile
# syntax=docker/dockerfile:1
FROM node:24-alpine AS base
RUN corepack enable
WORKDIR /app

FROM base AS deps
COPY package.json pnpm-lock.yaml ./
RUN pnpm install --frozen-lockfile

FROM base AS build
COPY --from=deps /app/node_modules ./node_modules
COPY . .
ENV NEXT_TELEMETRY_DISABLED=1
RUN pnpm build

FROM node:24-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production NEXT_TELEMETRY_DISABLED=1 PORT=8080 HOSTNAME=0.0.0.0
COPY --from=build --chown=node:node /app/.next/standalone ./
COPY --from=build --chown=node:node /app/.next/static ./.next/static
COPY --from=build --chown=node:node /app/public ./public
USER node
EXPOSE 8080
CMD ["node", "server.js"]
```

`apps/web/.dockerignore`: `node_modules`, `.next`, `.git`, `.env*`, `!.env.example`, `test-results`, `playwright-report`, `.features-gen`.

Health path for deploys: **`/api/health`**.

## Junior gotchas

- **Server vs Client Components.** Components are server-rendered by default. Add `"use client"` at the top only for files that need state, effects or browser APIs (`useState`, `onClick`, `window`).
- **`NEXT_PUBLIC_` variables are baked in at build time** and visible to every visitor. Never put a secret in one. Changing one needs a rebuild, not just a restart.
- **`next lint` no longer exists** (removed in Next.js 16) — use `eslint .`. Old tutorials still show it.
- **`middleware.ts` is now `proxy.ts`** in Next.js 16. Old tutorials use the old name.
- **shadcn/ui is not an npm dependency.** `shadcn add` copies component source into `src/components/ui/` — you own it, edit it freely, and it shows up in your diffs.
- **Tailwind v4 is configured in CSS** (`@theme` in `globals.css`), not in `tailwind.config.js`.
- **Use migrations, never `drizzle-kit push`, against shared databases.** Push skips the migration history that production relies on. The standalone image does not include drizzle-kit: run `pnpm db:migrate` from CI or your laptop, or add a small `src/db/migrate.ts` using drizzle-orm's `migrate()` and run it before `server.js`.
- **`next start` does not serve a standalone build** the same way as the container — test the real thing with `docker run` (see `/deploy`).
