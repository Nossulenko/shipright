# Stack profile: Go API (net/http)

## Overview

A small, fast REST API using Go's standard library.

| Layer | Choice |
| --- | --- |
| Runtime | Go 1.26 |
| HTTP | `net/http` with the standard `ServeMux` (method + path patterns like `GET /polls/{id}`) |
| Data | PostgreSQL via **pgx**, type-safe queries generated by **sqlc**, migrations with **goose** |
| Lint | `go vet` (+ golangci-lint if installed) |
| Unit tests | `go test` + `net/http/httptest` |
| Acceptance tests | **godog** (Cucumber for Go), run through `go test` |
| App folder | `apps/api` |

## When to pick it

- Your team knows Go, or you want a tiny, fast container with a single binary.
- You prefer explicit code over frameworks.
- **Pick another profile** for your first-ever backend unless you already know some Go — error handling and the type system take a little getting used to.

## Commands

```bash
mkdir -p apps/api && cd apps/api
go mod init github.com/<owner>/<repo>/apps/api
go get github.com/jackc/pgx/v5 github.com/pressly/goose/v3 github.com/cucumber/godog
go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest
go install github.com/pressly/goose/v3/cmd/goose@latest
```

| Task | Command | Used by |
| --- | --- | --- |
| Run | `go run ./cmd/api` | you |
| Lint | `go vet ./...` | verify |
| Tests (unit + godog) | `go test ./...` | verify |
| One scenario | `go test -run TestFeatures -godog.tags=@LUNCH-03` *(see below)* | `/build` |
| Build | `go build -o bin/api ./cmd/api` | you, Docker |
| Generate queries | `sqlc generate` | after editing `db/queries/*.sql` |
| New migration | `goose -dir db/migrations create add_polls sql` | schema change |
| Apply migrations | `goose -dir db/migrations postgres "$DATABASE_URL" up` | local, deploy |

## Layout

```
apps/api/
  cmd/api/main.go            reads PORT, builds the server, listens
  internal/http/server.go    NewServer(): routes, middleware, /health
  internal/http/*_test.go    httptest unit tests
  db/migrations/             goose SQL migrations — commit them
  db/queries/                SQL queries for sqlc
  internal/db/               sqlc-generated code (do not edit by hand)
  features_test.go           godog suite runner
  sqlc.yaml  go.mod  go.sum
  Dockerfile  .dockerignore  .env.example
```

`internal/http/server.go`:

```go
package http

import (
	"encoding/json"
	"net/http"
)

func NewServer() http.Handler {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		_ = json.NewEncoder(w).Encode(map[string]string{"status": "ok"})
	})
	return mux
}
```

`cmd/api/main.go`:

```go
package main

import (
	"log"
	"net/http"
	"os"

	api "github.com/<owner>/<repo>/apps/api/internal/http"
)

func main() {
	port := os.Getenv("PORT")
	if port == "" {
		port = "8080"
	}
	log.Printf("listening on :%s", port)
	log.Fatal(http.ListenAndServe(":"+port, api.NewServer()))
}
```

## Testing & BDD runner

`features_test.go` runs every feature file under `specs/` that is tagged `@api`, as part of `go test`:

```go
package api_test

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"

	"github.com/cucumber/godog"

	api "github.com/<owner>/<repo>/apps/api/internal/http"
)

type world struct {
	server   *httptest.Server
	response *http.Response
}

func (w *world) iRequest(path string) (err error) {
	w.response, err = http.Get(w.server.URL + path)
	return err
}

func (w *world) theResponseStatusIs(status int) error {
	if w.response.StatusCode != status {
		return fmt.Errorf("expected %d, got %d", status, w.response.StatusCode)
	}
	return nil
}

func InitializeScenario(sc *godog.ScenarioContext) {
	w := &world{}
	sc.Before(func(ctx context.Context, _ *godog.Scenario) (context.Context, error) {
		w.server = httptest.NewServer(api.NewServer())
		return ctx, nil
	})
	sc.After(func(ctx context.Context, _ *godog.Scenario, _ error) (context.Context, error) {
		w.server.Close()
		return ctx, nil
	})
	sc.Step(`^I request "([^"]*)"$`, w.iRequest)
	sc.Step(`^the response status is (\d+)$`, w.theResponseStatusIs)
}

func TestFeatures(t *testing.T) {
	suite := godog.TestSuite{
		ScenarioInitializer: InitializeScenario,
		Options: &godog.Options{
			Format:   "pretty",
			Paths:    []string{"../../specs"},
			Tags:     "@api",
			TestingT: t,
		},
	}
	if suite.Run() != 0 {
		t.Fatal("feature tests failed")
	}
}
```

To run a single scenario, temporarily change `Tags` to `"@LUNCH-03"`, or register godog's flags with `godog.BindCommandLineFlags("godog.", &opts)` in a `TestMain` so `-godog.tags=@LUNCH-03` works from the command line.

## Container

`apps/api/Dockerfile`:

```dockerfile
# syntax=docker/dockerfile:1
FROM golang:1.26-alpine AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /out/api ./cmd/api

FROM gcr.io/distroless/static:nonroot AS runtime
COPY --from=build /out/api /api
COPY --from=build /src/db/migrations /db/migrations
ENV PORT=8080
EXPOSE 8080
USER nonroot:nonroot
ENTRYPOINT ["/api"]
```

The distroless image has no shell or package manager — just your binary — so it is tiny and has almost nothing to attack. `.dockerignore`: `bin`, `.git`, `.env*`, `!.env.example`.

Health path for deploys: **`/health`**.

## Junior gotchas

- **Handle every `err`.** `if err != nil { return … }` is the Go way; never discard errors with `_` unless you can explain why.
- **Close what you open** — `defer rows.Close()`, `defer resp.Body.Close()` — or you leak connections.
- **Pass `context.Context` from the request** (`r.Context()`) into database calls so cancelled requests stop their queries.
- **Do not edit sqlc output** in `internal/db/`; change the SQL and run `sqlc generate`.
- **No shell in the runtime image** — debug locally with `go run`, not by `docker exec` into the distroless container.
